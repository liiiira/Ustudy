## Testing Environment

I set up a separate testing environment so tests don't interact with the development database.

The test setup includes:

- A dedicated PostgreSQL test database
- A separate `.env.test` configuration
- A Docker Compose file for the test database
- A script that starts the test database and runs the test suite

The goal is to make running the tests as simple as:
```bash
```
```bash
pnpm test
```

The script handles starting the required test infrastructure and then launches the test suite.

## API Testing

For API tests, I use Vitest together with Supertest.

Vitest handles the test runner, assertions, and test lifecycle.
Supertest sends HTTP requests directly to the Express application.

This allows me to test the API from the HTTP layer instead of testing controllers individually.

For example:

```js
const response = await request(app)
  .post("/api/v1/users")
  .send({
    username: "kira",
    password: "12345678",
    email: "kira@gmail.com",
  });
```
expect(response.status).toBe(201);

This approach lets me verify the complete request flow:

HTTP Request
     ↓
Middleware
     ↓
Controller
     ↓
Service
     ↓
Repository
     ↓
Test Database

The tests therefore verify not only individual functions, but also that the different layers of the backend work correctly together.
